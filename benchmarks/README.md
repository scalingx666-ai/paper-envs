# Benchmarks

Hand-authored tasks that meet the Terminal-Bench-Science bar. These are not
generated by the pipeline; each one is designed from a paper, calibrated against
independent implementations, and validated in Linux containers.

### `disagg-kv-retention`

The agent implements an online admission/eviction policy for a disaggregated
LLM serving pool. The verifier runs the submitted `RetentionPolicy` as an
unprivileged child over eight hidden workloads and applies five calibrated
performance gates plus contract and determinism checks.

| Submission | Reward | Result |
|:--|:--|:--|
| reference (decayed LFU) | 1 | 8/8, geomean 0.378 |
| independent CTLFU | 1 | 8/8, geomean 0.380 |
| independent SLRU | 1 | 8/8 tests at the boundary |
| starter LRU | 0 | fails geomean/total/p95 |
| hidden-trace cheat | 0 | contract + performance failure |
| empty | 0 | missing artifact |

Full gate table, threshold calibration, and anti-cheat details are in the
[task README](disagg-kv-retention/README.md). The task statement is
[instruction.md](disagg-kv-retention/instruction.md); the Harbor configuration
is [task.toml](disagg-kv-retention/task.toml).

### `async-rollout-scheduling`

The agent implements the batching and admission scheduler for a fully
asynchronous RL-VLA pipeline: environment shards emit rollout segments, an
inference server batches them, and a trainer consumes them while the policy
version advances. The verifier runs the submitted `SchedulerPolicy` as an
unprivileged child over eight hidden workloads and applies six calibrated
performance gates per workload plus aggregate, contract, and determinism
checks.

| Submission | Reward | Result |
|:--|:--|:--|
| reference (half/full thresholds) | 1 | 8/8, geomean 1.846, mean lag 2.49 |
| independent pair/full scheduler | 1 | 8/8, geomean 1.885, mean lag 2.52 |
| full-batch starter | 0 | fails lag and batch gates on 7/8 |
| age-first | 0 | fails lag on bursty/drift and speedup on low-overhead |
| half-batch | 0 | fails mean and p95 lag |
| one-at-a-time / train-immediate | 0 | fails throughput and freshness everywhere |
| no-op / hidden-trace cheat | 0 | stall / contract failure |
| empty | 0 | missing artifact |

Full gate table, margin analysis, and provenance details are in the
[task README](async-rollout-scheduling/README.md). The task statement is
[instruction.md](async-rollout-scheduling/instruction.md); the Harbor
configuration is [task.toml](async-rollout-scheduling/task.toml).

```bash
cd async-rollout-scheduling
docker build -t asyncrl-env:v1 environment
docker build -t asyncrl-tests:v1 tests
docker run --rm asyncrl-env:v1 sh -c \
  'python starter/check_policy.py --policy starter/policy.py'
docker run --rm -v "$PWD/solution/policy.py:/app/policy.py:ro" \
  asyncrl-tests:v1 bash /tests/test.sh
```

## What benchmark-grade means here

- **Held-out data.** The agent image contains a public dev set; the verifier
  contains a disjoint hidden set that is never mounted into the agent container.
- **Artifact-only grading.** Only `/app/policy.py` crosses the boundary. The
  verifier imports nothing from the agent's environment as root.
- **Isolation.** The policy runs as `nobody` under `setpriv` in an isolated
  interpreter (`-s -S`, no site-packages), with address-space, file-size,
  descriptor, process, and CPU limits. An audit hook denies sockets, file
  writes, process creation, and native-library loading; the hidden traces are
  unreadable. `authoring/evidence/isolation_check.py` exercises each attempt.
- **Calibrated gates.** Thresholds bracket at least one independent correct
  implementation and several defective comparators. A gate only the reference
  can hit is rejected.
- **Binary reward.** The task passes only if every conjunctive gate passes; the
  verifier writes a CTRF report and `reward.txt`.

## Reproducing

Each task directory is self-contained:

```bash
cd disagg-kv-retention
docker build -t kvret-env:v3 environment
docker build -t kvret-tests:v4 tests

# protocol check and public-workload harness
docker run --rm kvret-env:v3 sh -c \
  'python starter/check_policy.py --policy starter/policy.py'

# grade the reference
logs=$(mktemp -d)
docker run --rm \
  -v "$PWD/solution/policy.py:/app/policy.py:ro" \
  -v "$logs:/logs/verifier" \
  kvret-tests:v4 bash /tests/test.sh
```

The verifier needs a writable `/logs/verifier`; the policy mount can be
read-only because `test.sh` treats ownership changes as best-effort. The task
README shows the exact matrix of submissions and expected rewards.
